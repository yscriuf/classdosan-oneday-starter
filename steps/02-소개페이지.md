# 02 · 소개 페이지 만들기

**목표**: `design.md`(디자인 기준)와 `info.md`(무엇을 담을지)를 준비하고, 그 둘로 서비스 소개 페이지(`app/page.tsx`)를 만든다.

**A. design.md 준비 — 여러분이 직접 할 일 (hands-on)**
- refero(https://styles.refero.design/)에서 마음에 드는 디자인을 고르고, refero의 **Extended 탭 → ⬇ .md** 버튼으로 파일을 다운받아 **이 폴더에 넣게** 안내한다.
- refero에서 받은 파일은 항상 `DESIGN.md`(대문자)로 저장된다. 그 대문자 파일은 **지우고 소문자 `design.md`로 새로 쓴다**(macOS는 대소문자를 같게 보지만 배포용 Linux는 구분하므로 반드시 소문자로 통일). 내용은 네가 읽어 `design.md`로 정리한다. (CLAUDE.md의 한글 규칙이 자동 적용된다 — 여러분이 "참고해줘"라고 안 해도 됨.)

**B. info.md 정리 — 무엇을 담을지 문서화**
- 소개 페이지에 담을 헤드라인·기능·CTA를 여러분에게 물어 정리하고, 네가 `info.md`로 저장한다.
- **문서화 이유를 말해준다**: **"문서로 정리해서 AI에게 명령하면 훨씬 높은 퀄리티의 결과물을 얻을 수 있어요."** 소개 페이지는 이 `info.md`를 근거로 만든다.

**C. 소개 페이지 생성**
- `design.md` + `info.md`로 `app/page.tsx`를 만든다(네가 구현).
- 소개 페이지의 CTA(예: "대시보드 열기")는 본 서비스(`/app`)가 05단계에서 만들어지므로, **아직 링크로 연결하지 말거나** "곧 만들 예정" 상태로 둔다(지금 연결하면 클릭 시 404). 실제 연결은 05단계에서.
- **탭 제목 정리**: `app/layout.tsx`의 `metadata.title`이 아직 기본값 `"Create Next App"`이다 — 이걸 **여러분의 서비스 이름**으로 바꾸고 `description`도 한 줄 채운다. (배포하면 브라우저 탭 제목·검색 미리보기가 되므로 기본값 그대로 나가지 않게.)

**여러분이 직접 써보게 할 프롬프트**: 페이지에서 고치고 싶은 부분을 **여러분이 직접 문장으로** 수정 요청하게 코칭한다(예: "헤더 여백 더 주고 폰트 키워줘").

**완료 신호**: 소개 페이지가 localhost에 뜨고 여러분이 만족 + "됐어/다음".
